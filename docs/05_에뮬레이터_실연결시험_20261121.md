# 순정 내비 실연결 시험 (Pleos Connect Emulator)

시험일: 2026-11-21. 이전 문서들이 미검증으로 남긴 순정 내비 연결(장소 목록, 예상 시간, 경로 요청과 재조회)을 정상 동작하는 에뮬레이터에서 처음 확인한 기록이다. 실제 차량 시험은 아니다.

## 환경

| 항목 | 값 |

| 에뮬레이터 이미지 | Pleos Connect v2.1.0 (`RELEASE.release_connect_v2.1.0`), Android 14 / API 34, x86_64 |
| AVD | 2560×1440, 160dpi, RAM 4GB, Cold boot, `-gpu host` |
| 호스트 GPU | NVIDIA GeForce RTX 4070 Ti 12GB (gfxstream, Vulkan·GLES host), WHPX 가속 |
| 순정 내비 | `ai.umos.maps.android.navigation.app` 3.3.2-rc5-hotfix.3, NaviHelper 서비스 3.0.4 |

공식 문서는 이 에뮬레이터에 외장 그래픽카드를 필수로 요구한다(최소 RTX 3060 Laptop 6GB). 이전 작업의 "순정 지도 앱 응답 없음"은 이 환경에서 재현되지 않았다.

### ETA 단위 확인

현재 위치(성남 수정구)에서 즐겨찾기 3곳을 조회했다. 거리를 미터, ETA를 초로 보면 평균 속도가 도심 범위에 들어가고, 순정 안내 화면의 값과도 일치한다.

| 목적지 | rawEta | rawDistance | 초·미터로 본 평균 속도 | 순정 안내 화면 |
|---|---:|---:|---:|---|
| 코엑스 | 2097 | 15,049 | 25.8 km/h | (안내 시작 후 재조회로만 확인) |
| 롯데월드타워 | 2111 | 13,280 | 22.6 km/h | 36분 · 13km |
| 서울역 앞 호텔 | 2357 | 22,266 | 34.0 km/h | 40분 · 22km |

이 결과로 어댑터가 예상 시간을 분으로 바꿔 보고하도록 고쳤다(아래 "예상 시간 표시와 순정 지도 연동").

## 실제 데이터와 달랐던 가정 (어댑터 수정)

| 이전 가정 | 실측 | 수정 |
|---|---|---|
| 즐겨찾기의 `poiSubId`는 항상 있다 | 3건 모두 `null`, `poiProvider`는 빈 문자열 | `null`은 `""`로 받아 장소로 사용. `RouteInfo`는 `subId` NotNull이라 `""`, `TripRequest`는 Nullable이라 `null`로 보낸다. 빈 슬롯은 따로 건너뛴다. |
| 경로 요청 뒤 `onRoutingCompleted`가 온다 | 오지 않음. `RouteStarted` 직후 같은 밀리초에 `RouteEnded`, 이어서 `NavigationStatus`, `RouteStateInfo` | `RouteStarted`를 완료 신호로 보고 1.5초 뒤 재조회. 시작 직후의 `RouteEnded`/`RouteCancelled`는 전환으로 보고 판정을 재조회에 맡긴다. 시작 없이 온 종료는 기존대로 실패. 경로 요청 단계 제한 시간 30초. |
| 재조회 목적지 좌표가 요청과 0.000001° 이내로 같다 | 순정이 목적지를 도로 쪽으로 옮김: 호텔 29m, 코엑스 192m, 롯데월드타워 283m | POI id·subId 완전 일치는 유지하고, 좌표는 500m 이내 확인으로 완화 |

재조회 결과 `NaviMode=ROUTE_GUIDING`, `isRouting=false`, 약관 동의 `true`, 경로 옵션은 요청한 `RECOMMENDED`와 같았다.

## 예상 시간 표시와 순정 지도 연동 (같은 날 추가)

**예상 시간.** `TripInfo.eta`(초)를 반올림해 분으로 보고한다. `requestTrip`에는 경로 옵션 인자가 없으므로 기준은 `ETA_PLEOS_TRIP_DEFAULT_OPTION`(순정 기본 경로)이다. 출발 위치는 `getCurrentLocationInfo()`의 좌표를 약 1km 격자(`GRID100_위도×100_경도×100`)로 묶어 `originKey`로 쓴다. 이 키는 기기 안 기록에만 쓰고 밖으로 보내지 않는다. 위치가 1초 안에 오지 않으면 시간은 보여 주되 기준을 `PLEOS_TRIP_NO_ORIGIN`으로 두어 평소 대비 비교에서 뺀다. 홈 화면 실측: 코엑스 "37분 · 오전 11:01 도착 예정", 같은 시각 순정 경로 전체 보기 "11:02 AM · 36분 · 15km".

**경로선.** 순정 SDK의 예상 시간 응답에는 경로선 좌표가 없다(`routePoints`는 도착지 1개). 그래서 늘길이 직접 그리지 않고 순정 지도에 띄우도록 요청한다. 외부 경로 서버로 위치를 보내지 않으며, 순정 실제 안내 경로와 같다.

| 버튼 | 위치 | SDK 요청 | 결과 |
|---|---|---|---|
| 순정 지도에서 보기 | 홈 경로 요약 카드 (출발 전) | `requestNavigationScreen(POIDetailPopup(poiId, provider))` | 순정 지도에 목적지 핀과 상세 정보 |
| 순정 지도에서 경로 전체 보기 | 안내 확인 화면, 이미 안내 중 화면 | `requestNavigationScreen(OverviewRoute(RouteOverviewShowInfo(10000)))` | 실제 경로선(교통 색 구분)과 회전 안내 목록 |

`requestNavigationScreen()`에는 `pleos.car.permission.NAVI_CUSTOM_MAP` 권한이 필요하다(공식 문서 "Declaring permissions"). 처음에는 이 권한이 없어 `SecurityException`이 났고, 매니페스트에 추가해 해결했다. 기기에 정의된 Pleos 내비 권한 6개는 모두 protectionLevel `normal`이다. 화면 요청은 경로를 만들거나 바꾸지 않으므로 실패해도 연결을 끊지 않는다. 시연 모드에서는 순정 지도를 열지 않는다.

## 들를 곳 (경유지) — 같은 날 추가

친구 제안을 받는 서버는 아직 없으므로, 들를 곳은 순정 즐겨찾기·최근 목적지에서 고른다. 서버가 생기면 친구 제안도 같은 요청 흐름에 들어온다.

**출발 전 (함께 요청).** 홈의 "들를 곳" 카드에서 최대 2곳을 넣고 뺀다(목적지·중복 제외). 안내 시작 확인 창에 들를 곳이 함께 표시되고, `requestRouteWithWaypoints(RouteWithWaypointsRequest(RouteInfo, [RequestWaypointInfo...]))`로 한 번 보낸다. 재조회는 목적지·옵션과 함께 `getWaypointInfo()`의 경유지 목록이 요청과 같은지 확인한다. 미확인 요청 기록(journal)에 경유지도 남겨 앱 재시작 뒤 복구 검증에 쓴다.

**안내 중 (1곳 추가).** "들를 곳 넣기" → 장소 선택 → 확인 창 "경로에 넣기". 어댑터가 경로 상태·경유지 목록·현재 목적지를 먼저 읽고, 안내 중이 아님·경유지 2곳·이미 경로에 있음·현재 목적지·정차 아님이면 보내지 않는다. 통과하면 `addWaypoint(RequestWaypointInfo)`를 한 번 보내고, 이벤트 뒤 1.5초에 다시 읽어 판정한다. 같은 장소는 결과와 관계없이 다시 보내지 않는다.

| 시험 | 결과 |
|---|---|
| 롯데월드타워 + 들를 곳 코엑스, 함께 요청 | 순정 안내 시작, 재조회 목적지·경유지 일치(복구 경로로 확인) |
| 안내 중 현재 목적지를 들를 곳으로 | 보내기 전 차단 "지금 안내 중인 목적지예요" |
| 안내 중 이미 경유지인 곳 | 보내기 전 차단 "이미 경로에 있는 곳이에요" |
| 안내 중 호텔 추가 | `addWaypoint` → 재조회 경유지 1→2곳, 목적지 유지 → "들를 곳을 경로에 넣었어요" |
| 경유지 2곳에서 하나 더 | 보내기 전 차단 "이미 들를 곳이 2곳이에요" |
| 순정 경로 전체 보기 | 경유지 2곳(회색 핀)과 목적지를 지나는 경로선 |

**실제 동작과 달랐던 점.**

- `getWaypointInfo()`의 경유지 좌표가 (0, 0)이고 표시 좌표도 없다. id는 같고 `remainDistance`(15,000m)는 실제 경유지까지 거리와 맞았다. 그래서 경유지는 POI id·subId 완전 일치로 확인하고, 좌표는 순정이 값을 줄 때만 500m 이내를 본다.
- `addWaypoint` 뒤 이벤트 순서: 0.85초 뒤 `RouteCancelled` → 약 7초 재탐색 → `WaypointChanged(ADD)` + `RouteEnded`. 추가 중의 취소·종료는 실패가 아니라 재탐색이므로 재조회로 판정한다.
- 두 번째 자리(`SECOND`)로 보냈지만 순정은 `index=FIRST`로 넣었다. 방문 순서는 순정이 정하므로 경유지 비교는 순서를 보지 않는다.
- 앱을 다시 열어 "이미 안내 중"이면 장소 목록을 읽지 않아 들를 곳 후보가 비었다. 안내 중이고 정차했으면 목록을 읽도록 고쳤다.

자동 검사 `checks/StopChecks.java` 28건: 규칙(2곳·중복·목적지), 함께 요청, 확인 중 변경 시 이전 확인 폐기, 안내 중 추가, 같은 장소 재요청 금지, 미확인 뒤 재요청 금지, 거부 사유 표시, 정차 아님, 연타, 2곳 상한, 들를 곳을 지원하지 않는 연결은 버리지 않고 거부.

## 주행 중 차단·경로 옵션·다음 이동 (같은 날 오후)

**주행 중 차단.** Pleos Connect Virtual Console(`adb forward tcp:8088 tcp:8088`)에서 기어를 D로 바꿨다. Pleos 시스템이 늘길 화면 전체를 가리고 "주행 중에는 사용할 수 없습니다."를 표시했다(늘길은 주행 중 사용 앱으로 선언하지 않았다). 그 뒤에서 늘길도 "정차 상태를 확인한 뒤 조작할 수 있어요"를 띄우고 안내 시작·들를 곳 추가·바꾸기·넘기기를 잠갔다. 기어 P로 돌리자 다시 열렸다. 순정 지도 보기는 경로를 바꾸지 않으므로 잠그지 않는다.

**경로 옵션.** "빠른 경로"로 요청했지만 재조회 옵션은 `RECOMMENDED`였다. 순정 지도 앱 로그도 `currentRouteOption: RECOMMENDED`로, `RouteInfo`의 옵션을 쓰지 않고 순정 자체 설정으로 안내했다. `changeRouteOption(SHORT_TIME)`은 순정에 전달됐지만(`ChangeRouteOptionRequest`) 옵션은 그대로였고 옵션 변경 이벤트도 오지 않았다. 처리 방식:

- 목적지·들를 곳이 맞으면 안내는 확인으로 본다. 옵션만 다르면 `changeRouteOption`을 한 번 보내고(이벤트가 없으면 10초 뒤) 다시 읽는다.
- 그래도 다르면 "경로 성향은 순정 설정(추천 경로)으로 안내 중이에요. 순정 내비에서 바꿀 수 있어요."로 실제 상태를 알린다. 이전에는 옵션 차이만으로 정상 안내를 "결과 미확인"으로 잠갔다.

**미확인 잠금 해제.** 결과 미확인 뒤 순정 안내가 끝나면 늘길이 계속 잠겨 새 요청을 못 했다. 두 가지를 고쳤다.

- 재연결 조건이 "모드 전환 가능"이라 잠긴 상태에서는 재연결이 안 됐다. 작업 중이 아니면 재연결한다. 새 연결은 저장된 요청 기록(journal)으로 먼저 복구 검증을 한다.
- 복구할 때 순정이 안내 중이 아니면(`SAFE_GUIDING`, `isRouting=false`) 이전 요청은 더는 반영될 수 없으므로 기록을 해제한다. 안내 중이면 지금처럼 목적지를 대조한다.

**다음 이동 준비.** 확인된 이동은 세션 동안 잠겨 있어, 순정 안내가 끝나도 앱을 다시 켜기 전에는 다음 목적지를 고를 수 없었다. 이제 안내가 끝난 것("안내 중인 경로 없음")을 읽으면 "다음 이동 준비" 버튼을 보여 주고, 누르면 새 이동으로 홈에 돌아간다. 미확인 이동은 계속 잠근다. 세션 검사에 6건을 추가했다(미확인은 잠금 유지, 안내 중에는 대기, 종료 확인 후 새 이동, 새 이동은 한 번만 요청).

**release APK.** 외장 SSD의 기존 키(CN=Nulgil, SHA-256 `4fd503f2…945bc`)로 0.4(versionCode 4)를 서명했다. 0.2 → 0.3 → 0.4 업데이트 설치를 에뮬레이터에서 확인했다.

## 친구 들를 곳 (2026-11-21)

차(늘길 0.5, 연결 시험 모드)와 친구 페이지(`invite-web/`, 로컬 정적 서버, 휴대폰 크기 375×812)를 실제 초대 서버(Supabase, 서울 리전)에 연결해 시험했다.

| 단계 | 결과 |
|---|---|
| 초대 코드 만들기 | 차에서 코드 생성(6자리), 12시간 뒤 만료 시각 표시 |
| 친구가 보내기 | 코드 입력 → OpenStreetMap 장소 검색 → 지도 확인 → 보내기. 차는 10초 안에 목록에 표시 |
| 출발 전 담기 → 안내 시작 | `requestRouteWithWaypoints stops=1`. 재조회 일치, 친구 화면 "경로에 들어갔어요" |
| 안내 중 넣기 | `addWaypoint index=SECOND`, 재조회 경유지 1→2, 목적지 유지. 친구 화면 "경로에 들어갔어요" |
| 초대 끝내기 | 친구 페이지 새로 열면 "이 초대는 끝났거나 시간이 지났어요" |

**순정이 POI 없는 경유지를 받는지.** 친구 장소는 순정 POI가 아니라 좌표·이름만 있다. `RequestWaypointInfo`의 poiId·subId·provider를 빈 값으로 보냈더니 두 경로(출발 전 함께 요청, 안내 중 추가) 모두 순정이 받아 안내했다. 재조회 값은 `id=blank sub=null provider=blank name=same zero=true`: 좌표는 (0,0)으로 돌아오고 이름은 보낸 그대로였다. 그래서 친구 장소는 이름으로 대조하고(좌표가 오면 500m 이내), 경유지 수가 하나 늘었는지와 목적지 유지를 함께 확인한다. 요청 기록(journal)에도 이름을 남겨 복구 때 같은 기준을 쓴다.

**순서.** 안내 중 추가는 `WaypointChanged(ADD) index=FIRST`로 왔다. 순정이 가까운 순서로 경유지 순서를 다시 정하는 것으로 보인다. 늘길은 순서를 비교하지 않는다.

**상태 전달.** 차는 요청을 보낼 때 `REQUESTED`, 결과에 따라 `ADDED`·`UNCONFIRMED`, 운전자가 넘기면 `DISMISSED`를 서버에 쓴다. 정차 확인 등으로 아무것도 보내지 않았으면 `PENDING`으로 되돌려 친구가 계속 기다리게 한다(서버 전이 `REQUESTED→PENDING`을 추가). 서버 쓰기는 순서대로 하나씩 보낸다.

## 앱 안 지도 (2026-11-21, 0.6)

순정 지도의 바탕이 비어 있어 늘길 화면에 OpenStreetMap 타일 지도를 넣었다. 에뮬레이터(인터넷 연결)에서 타일이 내려오고, 현재 위치(순정 기본 위치, 성남 수정구)·들를 곳 1(롯데월드타워)·목적지(코엑스)가 맞는 자리에 찍혔다. 친구 들를 곳 화면에서는 친구 장소 2곳(선정릉, 석촌호수)이 목적지·들를 곳 핀과 겹쳐, 경로 핀을 제자리에 두고 친구 핀을 옆으로 옮겨 선으로 잇게 고쳤다. 시험 중 찾은 문제: 초대가 열려 있으면 10초마다 화면을 다시 그려 스크롤이 맨 위로 돌아갔다. 같은 화면이면 스크롤 위치를 유지하고, 제안 목록이 바뀌지 않았으면 다시 그리지 않게 고쳤다.

## 친구 페이지 공개 배포와 QR (2026-11-21, 0.6.1)

`invite-web/`을 Vercel(https://nulgil-invite.vercel.app)에 정적 파일로 배포했다. 배포된 10개 파일이 저장소 파일과 바이트 단위로 같은 것을 확인했다. 차 앱의 `invite_web_url`에 이 주소를 넣어 다시 빌드했다.

| 단계 | 결과 |
|---|---|
| 초대 코드 만들기 | 차 화면에 코드와 QR 표시. 화면 캡처의 QR을 읽으면 `https://nulgil-invite.vercel.app/?c=<코드>` |
| 친구가 보내기 | QR 주소로 열면 코드 입력 없이 장소 검색 화면. 서울숲 검색 → 지도 확인 → 보내기 |
| 차에 도착 | 친구 화면을 보고 있는 차에 15초 안에 목록·지도 핀(A)으로 표시 |
| 이번엔 넘기기 | 친구 화면이 "이번에는 넘겼어요"로 바뀌고, 그 뒤로 상태 확인을 멈춤 |
| 초대 끝내기 | 시험 코드 종료 |

서버 확인 간격: 차는 친구 화면에서 15초, 다른 화면에서 1분(앱이 뒤에 있으면 확인하지 않음). 친구 페이지는 보낸 뒤 2분 동안 5초, 그 뒤 30초, 탭이 가려지면 쉼, 결과가 정해지면 멈춤.

## 요청 제한과 초대 만료 (2026-11-21, 서버 `invite_limits`, 0.6.2)

실제 서버에 익명(공개 키)으로 호출해 확인했다. 시험 코드는 끝냈다.

| 시험 | 결과 |
|---|---|
| 한 이동에 1분 안에 4곳 보내기 | 3곳까지 저장, 4번째는 `TOO_FAST` |
| 초대를 끝낸 뒤 친구가 상태 조회 | 기다리던 곳은 `EXPIRED`, 이미 넘긴 곳은 `DISMISSED` 그대로 |
| 같은 때 차가 목록 조회 | 저장된 상태 그대로(`PENDING`, `DISMISSED`). 차는 `EXPIRED`를 받지 않음 |
| 끝난 초대에 보내기 | `TRIP_CLOSED` |
| 최근 10분 초대 60개 상태에서 만들기 | `TOO_BUSY` (트랜잭션 안에서 가짜 행을 넣고 시험한 뒤 되돌림) |
| 이틀 전에 끝난 초대 | 다음 초대 만들기 때 삭제됨 (같은 방식으로 시험 뒤 되돌림) |

친구 웹은 `EXPIRED`이거나 제안이 지워져 없으면 "초대가 끝났어요"를 보여 주고 확인을 멈춘다. 차는 `TOO_BUSY`면 "잠시 뒤 다시 시도해 주세요"라고 안내한다.

## 주행 중 도착한 제안 (2026-11-21)

순정 안내 중(코엑스)에 초대를 열고, Virtual Console(`adb forward tcp:8088 tcp:8088`, 브라우저로 `http://127.0.0.1:8088/`을 열어 둔 상태에서 `POST /vehicle/gear?gear=Drive`)로 기어를 D로 바꾼 뒤 친구가 봉은사를 보냈다.

| 단계 | 결과 |
|---|---|
| 기어 D | Pleos가 늘길 화면 전체를 "주행 중에는 사용할 수 없습니다"로 가린다. 앱은 일시정지되어 서버 확인도 멈춘다. 주행 중에는 순정 안내 화면만 보인다 |
| 기어 P | 늘길이 다시 보이고, 홈에 "친구가 보낸 곳 1곳 확인"이 강조되어 나온다 |
| 경로에 넣기 | 확인 창 → 안내 중 경로에 한 번 요청. 재조회로 확인해 "경로에 넣었어요" |
| 친구 쪽 | 서버 상태 `ADDED`, 친구 화면 "경로에 들어갔어요" |

정차 확인은 늘길 코드 외에 Pleos 자체의 주행 중 화면 제한이 한 번 더 막아 준다. 같은 시험에서 찾은 문제: 순정 오류 문장이 마침표로 끝나면 안내 미확인 문구에 마침표가 두 번 찍혔다("중단했습니다.."). 고쳤다.

참고: 갓 부팅한 에뮬레이터에서는 첫 안내 요청이 순정 응답 시간 초과로 미확인이 되었다. 순정 지도를 한 번 열어 둔 뒤에는 정상으로 요청됐다.

## 야간 모드 지도 (2026-11-21)

화면 밝기를 야간으로 바꾸고 친구 들를 곳 화면(들를 곳 1, 친구 장소 A·B)을 확인했다. 처음에는 밝은 타일 위에 반투명 검정만 덮어 지도가 주변 어두운 화면보다 훨씬 밝았다. 타일을 그릴 때 채도 45%, 밝기 50%로 낮추고(살짝 푸른 쪽), 출처 표시 바탕도 어둡게 바꿨다. 핀과 글자는 그대로 밝아 잘 보인다.

## "평소보다 N분" 표시 (2026-11-21, 모의 시연)

같은 요일·시간대 기록이 3일 쌓여야 판단하므로 실제 연결 모드에서는 하루에 확인할 수 없다. 모의 시연 모드에서 기록 저장에 동의한 뒤 개발 시연 버튼으로 같은 저장소에 3일치 예시 기록을 넣고, 실제와 같은 core 판정(`TrafficAdvisor`, 중앙값 대비 5분 이상이면서 20% 이상이면 경고)을 거쳐 화면을 확인했다.

| 시연 상태 | 화면 |
|---|---|
| 큰 지연 | 예상 44분, "평소보다 15분 더 걸려요", 지난 기록 버튼 |
| 평소와 비슷 | "평소와 비슷해요" |

실제 연결 모드의 예상 시간은 순정 내비(`requestTrip`)에서 받는다. 실제 기록 3일치로 같은 문구가 나오는지는 사흘 동안 같은 시간대에 써 봐야 확인할 수 있다.

## 폰에서 경로 보내기 (2026-11-21, 0.7)

| 단계 | 결과 |
|---|---|
| 폰 연결 | 차 내 일상 → 폰 연결 → QR(`phone.html?l=연결&k=폰 토큰`). 화면 캡처의 QR을 읽어 폰 페이지(로컬 정적 서버, 실제 서버)로 열면 연결이 폰에 저장되고 주소에서 지워짐 |
| 폰에서 보내기 | 봉은사 검색 → 지도 확인 → 차에 경로 보내기 → "차에 보냈어요" |
| 차가 받기 | 새로 확인(앱이 앞으로 올 때와 같음) → 홈에 "폰에서 보낸 경로예요", 목적지 봉은사, 순정 예상 29분 |
| 안내 시작 | 순정 재조회 `external=true nameMatch=true coordDeltaM=0 result=true` → "안내를 시작했어요". 폰 화면은 "차가 받았어요" |
| 연결 끊기 | 차에서 끊으면 서버 연결도 해제(revoked), 남은 장소 삭제 |

순정 POI가 아닌 목적지도 `requestTrip`(예상 시간)과 `requestRoute`(안내)를 받았다. 재조회 목적지 좌표는 보낸 좌표와 같았다(친구 들를 곳 경유지는 (0,0)으로 돌아왔던 것과 다름).

## 에뮬레이터 한계

- **지도 바탕 없음**(늘길 화면은 0.6부터 자체 지도로 보완): 순정 지도는 개발 서버(phase CORAL)의 빈 스타일 `connect_empty`를 쓴다. 바탕 지도는 그려지지 않지만 검색, 경로 계산, 경로선, 회전 안내는 동작한다. GPU 문제가 아니다(지도 렌더링 약 800 FPS, 누락 프레임 0).
- **GPS 위치**: 에뮬레이터가 보내는 NMEA 문장의 체크섬이 맞지 않아(`*47`) 순정 지도 앱이 위치를 버린다. 순정은 기본 위치(성남 수정구)를 현재 위치로 쓴다. `adb emu geo fix`는 Android 위치만 바꾸고 순정 지도에는 반영되지 않는다.
- **차량 상태**: 기어·도어 등은 Pleos Connect Virtual Console(`adb forward tcp:8088 tcp:8088` → `http://127.0.0.1:8088/`)로 바꿀 수 있다. 이번 시험에서는 사용하지 않았다.
- 순정 지도 앱 로그에 클라이언트 인증 정보가 평문으로 남는다. 시험 기록에 로그 전체를 붙이지 않는다.
