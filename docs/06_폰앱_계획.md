# 늘길 폰 앱(안드로이드) 계획

작성: 2026-11-21. 상태: 계획(구현 전).

## 왜 앱인가

지금은 친구와 운전자 모두 웹(`invite-web/`)에서 장소를 **검색**해서 보낸다. 실제로 사람들은 장소를 검색해서 옮기지 않고, 이미 보고 있던 카카오맵·네이버지도·카카오톡 대화에서 **공유**를 누른다. 화면 시안 p6("받은 지도 링크의 위치예요")도 이 흐름이다.

목표 흐름: **카카오맵/네이버지도/카톡에서 공유 → 공유 대상에서 "늘길" 선택 → 장소 확인 → 차로 보내기.**
웹은 공유 대상(안드로이드 공유 시트)에 들어갈 수 없으므로 앱이 필요하다.

## 앱이 하는 일

| 들어오는 길 | 앱 동작 | 보내는 곳 |
|---|---|---|
| 공유 시트(`ACTION_SEND`, text/plain)로 카카오맵·네이버지도 공유 | 공유 글에서 장소 이름·주소·링크를 읽어 좌표로 바꿈 → 지도로 확인 | 아래 둘 중 고름 |
| 링크 복사 후 앱 열기 | 클립보드의 지도 링크를 알아보고 "이 장소를 보낼까요?" | 같음 |
| 카톡으로 받은 초대 링크(`https://nulgil-invite.vercel.app/?c=코드`) | 앱이 설치돼 있으면 앱으로 열림(App Links), 없으면 지금 웹 | 친구 차 |

보내는 곳:
1. **친구 차의 들를 곳**(초대 코드가 있을 때): 기존 `submit_invite_suggestion`. 차에는 "경유지가 도착했어요" 카드가 뜬다.
2. **내 차의 목적지**(이 폰을 차와 연결했을 때): 기존 `send_phone_route`. 차에는 "폰에서 보낸 경로예요"가 뜬다.

서버와 차 앱은 지금 것을 그대로 쓴다. 새로 필요한 서버 기능은 아래 "링크 → 좌표" 하나다.

## 지도 링크 → 좌표

### 확인한 것 (2026-11-21)

네이버지도 앱에서 공유를 누르면 안드로이드 "텍스트 공유"(`ACTION_SEND`, text/plain)로 다음 글이 넘어온다(실기기 화면).

```
[네이버지도]
홈플러스 문경점
경북 문경시 모전로 65 홈플러스
https://naver.me/xAfHKpx5
```

- `naver.me` 단축 링크 → `map.naver.com/?...&pinType=site&pinId=13440359` → `map.naver.com/p/entry/place/13440359`. 장소 id만 있고 좌표는 없다.
- 카카오 로컬 키워드 검색("홈플러스 문경점") 1번 결과가 이름·도로명 주소가 같은 "홈플러스 문경점 / 경북 문경시 모전로 65"(36.58735, 128.19032). 이름이 정확히 같고 주소 앞부분이 같은 결과를 고르면 된다.
- 이름으로 못 고르면 주소 검색("경북 문경시 모전로 65")으로 건물 좌표(36.58731, 128.19038)를 쓴다.
- 카카오맵 단축 링크 `kko.to/...`도 따라가면 장소 id가 나온다(301). 카카오맵 공유 글은 아직 예시를 받지 못했다.

### 방법

| 출처 | 공유 글에 들어 있는 것(실기기에서 확인 필요) | 좌표 얻는 법 |
|---|---|---|
| 카카오맵 | 장소 이름, 주소, `https://kko.to/...` 단축 링크 | 단축 링크를 따라가면 `place.map.kakao.com/{장소 id}`. 카카오 로컬 키워드 검색(이름)을 하고, 결과의 `id`가 같은 항목의 좌표를 씀 |
| 네이버지도 | 장소 이름, 주소, `https://naver.me/...` | 단축 링크를 따라가 장소 id·좌표를 읽고, 없으면 이름·주소로 카카오 검색 |
| 구글 지도 등 | 링크에 좌표가 있으면 그대로 | 없으면 이름으로 카카오 검색 |

- 단축 링크 따라가기와 카카오 REST 키는 **서버(Supabase Edge Function `resolve-place`)**에 둔다. REST 키는 앱 패키지로 제한할 수 없어 앱에 넣지 않는다. 같은 함수를 친구 웹의 "링크 붙여넣기"에도 쓸 수 있다.
- 카카오 키는 무료 쿼터가 있는 기존 앱(공모전_플렉)의 키를 쓴다.
- 이름 검색 결과가 여러 개이고 id로도 못 고르면, 후보를 보여 주고 사람이 고른다.

## 구조(모듈)

```
nulgil/
  core/            (기존) Model 등 순수 자바 — 폰 앱도 그대로 사용
  phone/           (새) 안드로이드 폰 앱 모듈, minSdk 26
    share/         공유 받기: ShareActivity, ShareTextParser(카카오·네이버·구글 형식별)
    place/         PlaceResolver(서버 resolve-place 호출), 후보 고르기
    send/          InviteTarget(초대 코드들), PhoneLinkTarget(내 차 연결), 보내기·상태
    ui/            화면(작게): 장소 확인 + 보낼 곳 고르기, 보낸 기록
  server/supabase/functions/resolve-place/   (새) 링크 → { name, address, lat, lng, 후보 }
```

- 서버 호출(`SupabaseRpc`)은 차 앱의 `app/net`에서 공용 모듈로 옮겨 둘이 함께 쓴다.
- 지도는 카카오맵 안드로이드 SDK(네이티브 앱 키 + 키 해시를 공모전_플렉 앱에 등록) 또는 차 앱의 `RouteMapView`(OpenStreetMap 타일) 재사용. 처음엔 후자로 시작해 의존성을 줄인다.
- 초대 코드와 차 연결은 앱 저장소(SharedPreferences)에 둔다. 웹처럼 "최근 보낸 곳"도 앱에 둔다.

## 단계

| 단계 | 내용 | 확인 방법 |
|---|---|---|
| 1 | 실제 공유 글 모으기: 네이버지도 받음(위). 카카오맵·카톡 예시 추가 필요 | 사람이 직접 보내 준 예시 |
| 2 | `resolve-place` 함수 + 파서 검사(예시 글 → 좌표) | 함수 단위 시험, 실제 서버 |
| 3 | 폰 앱 뼈대: 공유 받기 → 장소 확인 → 초대 코드로 친구 차에 보내기 | 안드로이드 에뮬레이터에서 `adb shell am start -a android.intent.action.SEND --es android.intent.extra.TEXT "..."` |
| 4 | 내 차 연결(QR 스캔) → 목적지로 보내기 | Pleos 에뮬레이터와 함께 전 과정 |
| 5 | 초대 링크 App Links(앱 있으면 앱, 없으면 웹) | `assetlinks.json`을 Vercel에 배포 |
| 6 | 클립보드 링크 감지, 보낸 기록, 다듬기 | 실기기 |

## 정해야 할 것

- 공모전 제출물은 차량 앱이다. 폰 앱은 시연·사업성 설명용 동반 앱으로 둔다(2차 PT 시연 장면: 카카오맵에서 공유 → 차 화면에 카드 도착).
- 앱 하나로 친구·운전자 둘 다 쓰는지(추천: 하나, 보낼 곳만 고름).
- 배포 방식: 시연은 APK 직접 설치. 스토어 등록은 범위 밖.
