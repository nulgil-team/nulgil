# 날짜·시간대 계산 수정

작성일: 2026-11-05.

## 원인과 변경

기존 추천 코드는 이력을 저장된 요일·분으로 고른 뒤, 날짜 수는 timestamp를 86,400,000으로 나눈 UTC 날짜로 세었다. 같은 한국 날짜의 08:30과 09:15가 UTC 자정을 사이에 두면 서로 다른 날짜로 집계될 수 있었다. 저장 시의 요일·분이 조회 시간대와 다르면 후보 선정도 어긋났다.

이제 추천·교통 비교·데모 데이터 생성에 명시적 ZoneId를 전달한다. 이력의 selectedAt/observedAt을 해당 시간대의 날짜·요일·분으로 변환한다. 과거 저장 파일의 day/minute 필드는 호환을 위해 유지하되 이력 추천의 판단 근거로 사용하지 않는다. 파일을 일괄 변환하거나 기존 기록을 덮어쓰지 않는다.

Java 호출은 다음으로 바뀌었다.

```java
recommender.recommend(store.rules(), store.selections(), now, zone);
DemoFixtures.seed(store, now, zone);
```

모호한 이전 recommend 5인자 메서드는 제거했다. Android·PC 호출부도 명시적 시간대를 전달하도록 수정했다. DemoFixtures의 이전 4인자 seed는 Asia/Seoul 호환 진입점으로 남았으며 새 코드는 ZoneId 버전을 사용한다.

## 유지한 정책

- 직접 등록한 규칙은 현지 주간 요일·시각이다.
- 같은 현지 요일, 기준 시각 전후 60분을 비교한다. 자정을 넘어 인접 요일로 자동 확장하지 않는다.
- 최근 6주는 실제 경과시간 42×24시간이다.
- 선택 추천은 같은 현지 날짜를 최대 한 번 센다. 현재 날짜도 포함 가능하다.
- 교통 기준은 현재 현지 날짜를 제외하고 과거 날짜별 최신 표본 하나를 쓴다.
- 미래 이력과 범위 밖 이력은 제외한다. 교통 값의 유효기간은 기존 120초를 유지한다.
- 데모 시드는 해당 시간대에서 주간 벽시계를 유지하며, DST 조정 후 실제 현지 시각을 기록한다.

## 확인

수정 전 회귀 재현은 3건 모두 실패했다. 한국·미국 UTC 날짜 분할과 저장 요일 불일치가 포함된다. 수정 후 기존 핵심 검사 45개와 새 시간대 검사 25개가 통과했다.

새 검사는 양수·음수 UTC 오프셋, 자정·주간 경계, DST 시각 중복/누락의 유효 Instant, 시스템 기본 시간대 변경, 42일 경계·미래·교통 만료, 같은 현지 날짜의 교통 집계, 명시적 시간대의 데모 시드를 다룬다. 실제 차량 실행 검증은 별개다.

재현: `checks/check-core.ps1`. 증거는 `checks/evidence`에 보존했다.

구현 확인에 사용한 공식 문서: [Java Instant](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/time/Instant.html). 로컬 기존 core와 테스트를 우선 확인한 뒤, 명시적 시간대 변환의 API 의미를 확인했다.
